## 1. The five things this most CHANGES or CONFIRMS for HomeSynapse [LEAD WITH THIS]

1. **The sealed, no-DSL automation model is strongly CONFIRMED by HA's template scar tissue — but it exposes a missing "fail-closed-at-load" gate.** HA's Jinja templating produces silent never-fires: in HA 2026.6 the removal of legacy template syntax (deprecated in 2025.12) caused automations to "silently fail instead of throwing an error" — "no red error banners… You just notice at 2 AM that the porch lights never turned off." The HA maintainer explicitly refused to make a failed availability template render the entity unavailable ("Sorry, I'm not going to implement this," GitHub Discussion #3462) — a maintainer "out-of-scope" statement, which is gold-grade evidence that the template class is unfixable in-place. **CONFIRMS** the no-DSL anti-requirement. **Action:** add an explicit definition-validation-at-load gate to the M7 charter that refuses to load (fail-closed, surfaced) any automation referencing an unknown trigger ID or entity, rather than loading it into a silently-dead state.

2. **Bind posture is the single most dangerous app-bootstrap footgun — HA shipped a CVSS 9.7 default-bind failure as recently as March 2026.** CVE-2026-34205 showed add-ons in host network mode exposed unauthenticated endpoints to the whole LAN because the OS "do[es] not configure firewall rules to restrict access to the Docker bridge interface." This compounds the CVSS 10.0 Supervisor auth-bypass (CVE-2023-27482) via path traversal `/api/hassio/app/.%2e/supervisor/info`, which "is claimed to be used by 74.9% of active installations" and yielded "account takeover… and remote code execution." **SHARPENS** the "auth mandatory on every external interface, no local-trust exception" lock. **Action:** the app-bootstrap charter must enforce loopback-default bind, require explicit opt-in for LAN exposure, and enforce auth *before* main() exposes the surface — never bind-all-by-default, and never treat an interface as "internal."

3. **The "machine-local root key at MVP" posture must be communicated honestly — the field punishes "encrypted but the key is on the same disk" overclaims.** Eufy marketed "No Clouds," "no one has access to your data but you," then was caught uploading facial-recognition thumbnails to AWS; "Now that Anker has been caught in some big lies, it's going to be hard to trust whatever the company says next." **WARNS-AGAINST** any positioning that implies at-rest encryption protects against an attacker with physical disk access at MVP. **Action (route to strategy/PM):** the crypto-lane threat-model doc must state plainly that the machine-local root key protects against disk theft only after the Tier-2 (passphrase/TPM) upgrade; do not let marketing imply otherwise.

4. **Zero-config-no-passphrase is a real brand asset, but HA's "encryption key lost = data gone forever" is the cautionary tail.** HA made encrypted backups mandatory in 2025.1 and users are stranded: "Without the encryption key, there is no way to restore an encrypted backup. Nabu Casa does not store your encryption key." Migration to new hardware broke because "the key for the 'new' device is autopopulated and I can't enter the one from my emergency restore kit" (Issue #134162). **SHARPENS** the backup/restore co-design. **Action:** design the machine-local-root → backup-portability bridge now (an explicit, user-exportable recovery artifact tied to crypto-shred scopes), before users author definitions.

5. **The cloud-death graveyard validates the local-first motivation precisely — and names the exact mechanism HomeSynapse must never reintroduce: cloud-gated initial configuration.** Insteon's hubs needed servers "as part of initial configuration"; after the April 2022 shutdown, "users who factory reset… are now left with hubs that are essentially bricked." Revolv's CEO Arlo Gilbert (Televero Health) wrote on April 4, 2016 that "On May 15th, my house will stop working… This is a conscious intentional decision by Google/Nest," with users given only 75 days' notice. **CONFIRMS** local-first. **Action:** confirm no HomeSynapse first-run/onboarding step (including cipher activation) makes a network call that could become a brick-point — verify in the app-bootstrap charter (assumption to verify with PM).

## 2. Per-system deep dives

### Home Assistant
**Architecture:** Python Core + Supervisor + HAOS + add-ons; event bus, state machine, Recorder (SQLite default) for history, Jinja2 templating, monthly release train (first Wednesday).
**MISTAKES:**
- **Template fragility / silent failure (AX-5).** HA 2026.6 removed legacy template syntax; automations "silently fail instead of throwing an error." Docs admit triggers/conditions "are checked on change, not continuously," and `'None' has no attribute 'state'` errors are endemic. Maintainer declined to fail-closed on availability-template render failure (GitHub Discussion #3462).
- **Supervisor auth bypass CVE-2023-27482 (AX-1), CVSS 10.0.** Path-traversal at `/api/hassio/app/.%2e/supervisor/info` gave an "unauthenticated user… access [to] any Supervisor API leading to account takeover… and remote code execution"; the Supervisor integration "is claimed to be used by 74.9% of active installations." Fixed in Supervisor 2023.03.1/2023.03.3 and Core 2023.3.2, auto-rolled via Supervisor auto-update (elttam advisory; HA blog Mar 8 2023).
- **CVE-2026-34205 (AX-1), CVSS 9.7.** Host-network-mode add-ons exposed unauthenticated endpoints to LAN; "this configuration does not restrict access… allowing any device on the same network to reach these endpoints." Fixed in Supervisor 2026.03.2 via systemd firewall rules (GHSA-gh5m-4m97-c95h).
- **CVE-2023-41897 clickjacking (missing X-Frame-Options); 2023.12 leaked all usernames** to unauthenticated LAN requests "to make the login more user-friendly" (fixed 2023.12.3).
- **Recorder/SQLite DB blowups (AX-6/AX-10).** In 2024.7.x a purge bug made the DB "bloat out to 13GB" and "recorder stop writing to the DB until HA is restarted" (Issue #117263); legacy purge failures (Issue #92120); purge can corrupt the DB — "database disk image is malformed" (Issue #115765). Repack rewrites the entire DB and needs "as much free temporary space… as the size of your database."
- **Breaking-change tax (AX-7).** Monthly releases with a dedicated "Breaking Changes" section; "reading the release notes is not just a suggestion—it is a requirement for system stability."
- **Backup/restore data-loss (AX-4).** Mandatory encrypted backups since 2025.1 stranded users on hardware migration (Issue #134162).
**STRENGTHS:**
- **Automation modes governance (AX-5) — adopt the mechanism.** Exactly four modes: `single` (default, "Do not start a new run. Issue a warning."), `restart`, `queued`, `parallel`. `max` caps concurrent/queued runs (default 10, valid only for queued/parallel); `max_exceeded` controls warning severity (default `warning`, settable `silent`). This is HomeSynapse's bounded-cascade governance template.
- **`continue_on_error` (AX-5).** Per-action boolean (default `false`) on all actions to proceed past a failed action — a deterministic alternative to try/catch.
- **Auto-backup-before-update + one-click rollback (AX-2/AX-7).** "An automatic backup is taken before every update so you can roll back." Plus beta channel and continuous integration testing across hundreds of integrations.

### openHAB
**Architecture:** Java/OSGi (Apache Karaf), item/thing model, Next-Gen Rule Engine (NGRE).
**MISTAKE/lesson (AX-2/AX-7):** Historically tied to Quartz scheduler with non-standard cron; the maintainers ripped it out — "All traces of Quartz have been completely removed. The Timer class now works with our own scheduler" (PR #1451), and also replaced the "classic" rule engine. Lesson: an external scheduler dependency with its own semantics becomes a migration liability.
**STRENGTHS:**
- **Explicit numbered startup levels (AX-2) — adopt directly.** openHAB defines a startlevel ladder: "00 OSGi framework started; 10 bundles activated; 20 model entities loaded; 30 item states restored; 40 rules loaded and parsed; 50 rule engine active; 70 UI up." "Startlevels less than 40 are not available as triggers because the rule engine needs to start up first." This is a clean SystemLifecycleManager phase model for HomeSynapse's main()-wiring.
- **OSGi modularity** for runtime add-on lifecycle without restart (heavier than needed on Pi-4, but the dependency-injection discipline is worth noting).

### Hubitat
**Architecture:** Local-first hub, app/driver model, Rule Machine.
**STRENGTH (AX-9/AX-10):** Pure local execution — "automations execute in milliseconds without a network round-trip, and your home keeps working through internet outages, server maintenance, and company acquisitions." Explicitly positioned as the anti-cloud-death hub; supports local backup/restore of apps AND devices. Confirms HomeSynapse's local-first value prop and that "automations run during internet outage" is a sellable property.
**MISTAKE/lesson (AX-5):** Rule Machine is "the most flexible automation builder in a consumer hub" but power-user-only; the dated UI is "honest criticism." Lesson: maximal flexibility ≠ maintainability — supports the sealed-model + good authoring-UX bet.

### SmartThings
**Architecture (post-2022):** Migrated from Groovy cloud IDE to Lua-based Edge drivers + Rules API, localizing execution.
**MISTAKE (AX-7) — the forced-migration case study.** Official notice: "Beginning October 15th… adding new Groovy code and logging will be turned off. It will totally be shutdown at the end of December [2022]." Custom Device Type Handlers had to be rebuilt; "for some devices… capabilities may change… If after migration, that device is no longer compatible with its previously associated Automations, it will be removed from its existing Routines or Scenes." "There is no published schedule… nor will you receive a notification that the migration has occurred." Even when the platform *survived*, forced migration broke user setups. **Lesson:** confirms the need for a versioning + deprecation policy committed *before* users author definitions.
**STRENGTH (AX-8):** The migration's *goal* was sound — moving "processing… from the cloud to your hub, creating faster and more reliable connections which operate locally." Validates local execution.

### Apple HomeKit / Home
**Architecture:** Closed-but-trusted, HAP (HomeKit Accessory Protocol), home hub (Apple TV/HomePod), HomeKit Secure Video.
**MISTAKE (AX-2/AX-7) — architecture-migration reliability stumble.** The iOS 16.2 "new Home architecture" (late 2022) broke setups: devices "stuck in 'updating' or 'configuring,'" accessories "disappeared," "HomeKit Secure Video no longer recording." Apple "pulled the option to upgrade" and added it to an "internal list of major issues" reserved for "widespread and noteworthy problems," re-releasing only in iOS 16.4 (Feb 2023). Then in 2026 the *old* architecture lost all support (Feb 10, 2026 deadline), stranding users on iOS versions too old to upgrade. **Lesson:** even a security-leading vendor caused a reliability disaster with a one-shot, destructive state-model migration; HomeSynapse's event-sourced replay + deterministic migration must be safer than a destructive in-place upgrade.
**STRENGTH (AX-9):** Strong security/privacy brand and a closed-but-trusted accessory-attestation model (HAP) — the trust-brand template, to be communicated as a property.

### Matter / Thread
**Architecture:** Interoperability standard (Matter) over Thread/Wi-Fi/Ethernet; QR/numeric setup codes + BLE commissioning; multi-admin.
**MISTAKE (AX-8) — promise-vs-field gap.** "Matter does not yet do a good job of informing you what went wrong when the process fails… largely a matter of guesswork." Multi-admin "quietly fails": sharing a device "can take upwards of five minutes with no guarantee of success." IKEA acknowledged setup failures; The Verge traced it to "Apple, Google, and Amazon… pursuing their own agendas." Thread 1.3 border-router certs no longer accepted after Jan 1, 2026; older setups fragment into "separate islands." **Lesson:** the field's pain is poor *observability of failure* — directly informs HomeSynapse's ReachabilityTrigger needing explicit, surfaced states, not silent guesswork.
**STRENGTH (AX-8):** Multi-admin's *intent* (a device controllable by multiple ecosystems without lock-in) and QR/BLE onboarding are the right primitives; local control is real once commissioned.

### Node-RED
**Architecture:** Visual flow programming on Node.js; event-driven; runs well on Pi.
**MISTAKE (AX-5) — flow sprawl / unmaintainability.** "Node-RED flows can become spaghetti over time… a fragile system that only you understand." Users build their own per-flow "reliability framework" with Catch nodes. An add-on UI bug pushed a long-time user to migrate to native HA automations. **Lesson:** unconstrained visual wiring trades early velocity for long-term unmaintainability — supports the sealed trigger/condition/action model with run-trace/lineage built in (not bolted on per flow).
**STRENGTH (AX-5):** Live in-flow output visualization ("as it runs, I can even see outputs under the nodes") — the run-trace/lineage UX worth adopting in HomeSynapse's authoring surface.

### ESPHome
**Architecture:** Declarative YAML compiled to firmware; validates the *entire* config before processing.
**STRENGTH (AX-7) — config ergonomics to study.** "The entire contents will be read before any validation or processing is done"; YAML anchors/aliases (`&anchor`/`*alias`) and merge keys (`<<: *anchor`) for DRY config reuse. Compile-time validation catches errors before deploy — a fail-closed-at-load precedent.
**MISTAKE (AX-7/AX-10):** Validation can hang for minutes on certain component definitions (community report on 2025.8.1 with `bme68x_bsec2_i2c`); package-scoped config can fail validation (Issue #1487). Lesson: declarative validation must be bounded/timely or it becomes its own footgun.

### Zigbee2MQTT / Z-Wave JS
**Architecture:** Local radio stacks; MQTT (Z2M) and JS driver (Z-Wave JS) bridges.
**STRENGTH (AX-8) — reachability semantics to adopt verbatim.** Z2M `availability` feature distinguishes `active` (non-battery, check-in every 10 min default, then pinged) vs `passive` (battery, 25 h default, `timeout: 1500`), publishing `online`/`offline` to `zigbee2mqtt/[FRIENDLY_NAME]/availability` (retained MQTT) plus a `last_seen` attribute. Z-Wave JS node status = `alive` / `dead` / `asleep` / `awake` + "Node Ready," with `zwave_js.ping` recovery. **This is the exact vocabulary HomeSynapse's ReachabilityTrigger should model** — crucially distinguishing "battery device legitimately asleep" from "mains device dead" to avoid false-alarm triggers.
**MISTAKE (AX-8 security) — S0 downgrade ("Z-Shave").** Pen Test Partners showed S2 pairing can be downgraded to S0, whose network key is "encrypted with a string of zeroes" (`0000000000000000`). "If an S0 network key is obtained, all S0 devices connected in the past and future are placed at risk." Silicon Labs called it a "conscious choice… to discount this non-vulnerability" for backward compatibility. The S2 controller only "notif[ies] the user… after the fact" — "We feel this will be ignored or overlooked." **Lesson:** backward-compatibility security downgrades are a trap; surface security-downgrade events loudly and fail-closed where possible.

## 4. Cautionary post-mortems (the graveyard)

- **Revolv (Nest, 2016) — cloud-death by intentional brick.** CEO Arlo Gilbert (Televero Health), Medium, Apr 4 2016: "On May 15th, my house will stop working… This is a conscious intentional decision by Google/Nest." Per Nest's statement (via Fortune), users got only "75 days" notice via "in-app notifications and a message on the Revolv site." Mechanism: total cloud dependency for *all* function; FTC noted consumers "would not expect the Revolv hubs to become unusable." **HomeSynapse property that prevents it:** local-first, no cloud dependency for core function. *Already prevented.*
- **Insteon (2022) — cloud-death + cloud-gated re-config brick.** Servers went dark overnight April 2022; "physical switches… [still] operating, but… no automation and scheduling." Critical second-order mechanism: "users don't factory reset… those have to communicate with the… servers as part of initial configuration"; reset = permanent brick. **HomeSynapse property:** local-first core. **GAP to verify:** confirm NO first-run/onboarding/cipher-activation step requires a network call — this is the exact Insteon brick-vector. *Verify in app-bootstrap charter (assumption to verify with PM).*
- **Wink (2020) — sudden subscription-or-brick.** Announced May 6, 2020 for a May 13, 2020 cutoff (≈one week): "Should you choose not to sign up for a subscription you will no longer be able to access your Wink devices… and your automations will be disabled on May 13" (later pushed to May 20, then July 27). The box said "no monthly fees." Mechanism: control + automation gated behind a cloud subscription. **HomeSynapse property:** local-first, no cloud-required control. *Already prevented.* **Lesson for strategy:** the betrayal was the *terms-of-service rug-pull*; HomeSynapse's local ownership is the antidote, sellable as such.
- **SmartThings Groovy (2022) — forced migration even though the platform lived.** Mechanism: deprecated execution model (Groovy DTHs/SmartApps) with hard cutoff (Dec 31 2022), no migration schedule, silent capability loss. **HomeSynapse property:** stable trigger IDs + sealed model + (needed) versioning/deprecation policy. **GAP:** the deprecation-policy commitment is not yet a locked HomeSynapse fact — *flagged as the AX-7 action.*
- **Eufy (2022) — privacy-brand self-immolation.** Mechanism: "local-only" marketing contradicted by cloud uploads + unauthenticated VLC streams. **HomeSynapse property:** auth-mandatory-everywhere + genuine local-first + honest crypto posture. *Prevents the technical failure; the LESSON is communication honesty (route to PM).*
- **Mirai (2016) — the IoT default-credential botnet.** Mechanism: brute-forced Telnet/SSH with 62 hardcoded default credential pairs (primary `root`/`xc3511`); the Oct 21 2016 Dyn attack peaked at ≈1.2 Tbps via 100,000+ bots. **HomeSynapse property:** auth-mandatory-everywhere with zero-config-still-authenticated (no default/shared secret). *Already prevented, provided zero-config never devolves into a shared/predictable bootstrap secret — verify in app-bootstrap charter.*
