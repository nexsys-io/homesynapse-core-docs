### 6.3 Bootstrap sequence — `HomeSynapseCore.start()`

Synchronously on the calling thread (must be platform per LTD-19 / `JacksonWarmup` requirement):

1. Construct `SqlitePersistenceLifecycle(dbPath, config.persistence(), clock, homeId, EventTypes.CORE_PRODUCTION_EVENT_CLASSES + IntegrationEvents.LIFECYCLE_EVENT_CLASSES aggregated)`. Call `start()`. Wait for the returned `CompletableFuture<Void>`.
2. Construct `BusMetrics.jfr()`.
3. Construct `InProcessEventBus(eventStore, checkpointStore, clock, readConnectionFactory, jfrMetrics, () -> writeCoordinator.queueSize(), config.eventBus())` — using the production 7-arg ctor that takes `EventBusConfig`.
4. Construct `CheckpointSerializer(checkpointMapper)` — the M3.5b checkpoint mapper.
5. Construct `SqliteStateStore(viewCheckpointStore, checkpointSerializer, "entity_state")` — already initializes from the latest checkpoint.
6. Construct `DerivedWriteRateLimit(clock, jfrMetrics, "state_projection")` — production 3-arg ctor.
7. Construct `StateProjection.create(...)` with the 11 ctor params including `SqliteStateStore` (which implements `StateCheckpointSource`) and the `DerivedPublishGate gate = rateLimit::acquire` adapter.
8. Subscribe the projection via `eventBus.subscribeRuntime(projectionSubscriberInfo, projection)`.
9. Construct `QueueSaturationHealthCheck(() -> writeCoordinator.queueSize(), clock, 5000, 10000, 5, healthSignalHandler)`.
10. Construct `SharedScheduler(rateLimit, healthCheck)` — starts the two scheduled tasks.
11. Construct `MaterializedStateQueryService` placeholder — actual instantiation deferred to M3.6e. `stateQueryService()` returns `null` until then.
12. Return `CompletableFuture.completedFuture(null)`.

**Shutdown order (reverse):** scheduler → projection unsubscribe → bus reset → persistence lifecycle stop → SqliteStateStore close (if applicable). Each step idempotent. `stop()` is callable multiple times; only the first run executes the sequence.

### 6.4 Behavioral contracts

- **Single-shot start.** `start()` is not idempotent in the same sense as the persistence lifecycle — calling it twice on the same instance throws `IllegalStateException`. (`HomeSynapseCore` is constructed once per process.)
- **Lifecycle ownership.** `HomeSynapseCore` owns all subsystem lifecycles. External callers do not call `eventBus.reset()` or `persistenceLifecycle.stop()` directly; they call `homeSynapseCore.stop()` and the facade fans out.
- **Shared-scheduler discipline.** The `SharedScheduler` is single-threaded by design (`Executors.newSingleThreadScheduledExecutor`). The two scheduled tasks must each complete within their tick budget (50 ms refill, 1 s tick) — otherwise tasks queue and skew. `tick()` and `refill()` are documented as non-blocking; verified by their unit tests.
- **`ReadinessSource.mode()` semantics.** Returns the current `SubscriberMode` of the state projection. M3.6e's filter consults this to gate REST traffic.
- **`SqliteStateStore` as `StateCheckpointSource`.** The promoted-public `serialize(int)` and `loadedProjectionVersion()` satisfy `StateCheckpointSource`'s contract. No new methods, no behavior change — only a visibility flip and an `implements` clause.

### 6.5 STOP-on-Mismatch gates

- G1: M3.6a, M3.6b, M3.6c all complete on `main` before M3.6d issues. The composition root cannot construct correctly without the wired profile + parameterized bus + per-module manifests.

- G3: The lifecycle module's existing `SystemLifecycleManager` is NOT replaced — `HomeSynapseCore` is a parallel facade that, when later merged with `SystemLifecycleManager`, becomes the system-wide lifecycle coordinator. M3.6d does not touch `SystemLifecycleManager`.
- G4: No public API exposes a `null` `stateQueryService()` accessor without warning — Javadoc on the accessor states "returns null until M3.6e lands; final wiring is in M3.6e."
